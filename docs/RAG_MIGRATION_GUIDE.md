# Fibi RAG Migration Guide

This guide covers migration from the v0.17 small-memory RAG implementation to
the next-generation local RAG architecture.

## What Changes Automatically

`RAGMemoryRepository.initialize()` is migration-safe. On startup it adds missing
columns to existing `rag_memories` tables:

- `source_id`
- `source_uri`
- `source_title`
- `source_timestamp`
- `provenance_json`
- `expires_at`

It also creates new tables when absent:

- `rag_documents`
- `rag_document_chunks`
- `rag_memory_events`

Existing memories remain readable. Existing FAISS indexes are reused when the
active-memory count matches the vector count; otherwise the service rebuilds the
index locally.

## Recommended Upgrade Steps

1. Back up `data/fibi_memory.db`.
2. Start Fibi once or instantiate `RAGMemoryService`.
3. Run:

```powershell
python tests\smoke_v017_rag_memory.py
python tests\smoke_v019_rag_memory_v1.py
python tests\smoke_v021_rag_nextgen.py
python eval\benchmark.py --dataset eval
```

4. If the benchmark reports failures, inspect the JSON `failures` field.

## Rollback

The migration only adds columns/tables. Older code can ignore the new columns,
but indexes written by newer code should be regenerated by running the old
service's rebuild path if rolling back.

## Privacy

All migrations are local SQLite operations. No cloud API, NVIDIA endpoint, or
NeMo Retriever service is contacted.
